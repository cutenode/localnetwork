# Flags

A flag turns a feature on for some people before everyone. The flags themselves are files in [`flags/catalog/`](../../../../../flags/README.md), which locallibrary reads too. Staff set who each is on for at `/admin/flags`: every account, a percentage of accounts, [flag groups](../../../../../GLOSSARY.md) at `/admin/flags/groups`, or single accounts, and then signed-out visitors. "Off for everyone" turns a flag off and keeps all of that for when it's back on. Admins manage all of it, and on the Staff page they can give a moderator either part: flags, or flag groups. Every change is in the audit log. The list marks a release flag "Ready to remove" once every account and signed-out visitors have had it for 30 days.

To see a flag without changing it for anyone, staff with the flags grant can turn it on or off for their own browser from its page. The preview is a cookie signed with their session, lasts an hour, shows a banner on every page until it's cleared, and is audited. In development and tests, `FLAG_OVERRIDES=key=on,other=off` forces flags for every request instead; the app won't start with it in production ([ADR 0010](../../../../../docs/adr/0010-flags-turn-off-and-preview-without-touching-targeting.md)).

What's set is kept as `staff.flag` and `staff.group` records in the staff space, indexed into SQLite and held in memory, so reading one on a request costs nothing. Pages read `data.flags?.key` and server code `locals.flags.key`, worked out once per request. A signed-out visitor gets a release flag only once staff turn it on for them, which waits until every account has it; an ops flag reaches them whenever every account has it, everyone or 100% ([ADR 0018](../../../../../docs/adr/0018-signed-out-visitors-come-last.md)). locallibrary can't read the staff space, so `computer.localnetwork.flags.getFlags` tells it the public gates and whether it's targeted ([ADR 0006](../../../../../docs/adr/0006-locallibrary-asks-the-website-for-flags.md)).
