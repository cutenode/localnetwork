# Local Network design system

The look of the product page: dark ink, white type, and colour only where DJ data puts it.

## Rules

- **No brand accent.** Colour comes from DJ data: waveform bands, phrases, track colours. Section eyebrows borrow one each (`Eyebrow` tones). Status colours are for status only.
- **One primary action per view.** `Button` primary is white on ink. Everything else is `secondary` or `ghost`.
- **Words in Instrument Sans, data in JetBrains Mono.** Numbers, keys, BPM, record names and eyebrows are mono.
- **Every text colour reads at 4.5:1.** Text on a data colour goes through `onColour` (`contrast.ts`), which picks the ink and darkens the colour when neither ink reads. Stories fail their test on any accessibility violation.
- **Surfaces step up, never sideways.** `canvas`, then `sunken` for alternate sections, `surface` for cards, `well` for inputs and insets. Borders are `line`; controls use `line-strong`.

## Where things live

- `theme.css`: the tokens, fonts and base styles. Import it after `@import 'tailwindcss'`.
- `data-colors.css`: generated from `packages/tokens/colors.json`, the colours the player and the HTML report also use. After editing that file, run `TOKENS_BLESS=1 pnpm vitest run --project server src/lib/ui/data-colors.test.ts`.
- `*.svelte`: the components. Each has stories beside it, and `ui.svelte.test.ts` tests their behaviour.
- **Patterns/Homepage**: the product page built from these pieces, on desktop and on a phone. Its events and match scores are examples.

## Checks

`pnpm test:storybook` renders every story in Chromium and fails on an accessibility violation. It runs in `pnpm verify`.
