# Local Network design system

The look of the product page: dark ink, white type, and colour only where DJ data puts it.

## Rules

- **No brand accent.** Colour comes from DJ data: waveform bands, phrases, track colours. Section eyebrows borrow one each (`Eyebrow` tones). Status colours are for status only.
- **One primary action per view.** `Button` primary is white on ink. Everything else is `secondary` or `ghost`.
- **Words in Instrument Sans, data in JetBrains Mono.** Numbers, keys, BPM, record names and eyebrows are mono.
- **Every text colour reads at 4.5:1.** Text on a data colour goes through `onColour` (`contrast.ts`), which picks the ink and darkens the colour when neither ink reads. Stories fail their test on any accessibility violation.
- **Surfaces step up, never sideways.** `canvas`, then `sunken` for alternate sections, `surface` for cards, `well` for inputs and insets. Borders are `line`; controls use `line-strong`.
- **The type scale carries the weight.** `text-emphasis`, `text-heading`, `text-title` and `text-display` are semibold on their own; write `font-normal` for the rare one that isn't. The smaller sizes are regular.
- **Reach for a shared class before writing a long one.** `btn-*` and `btn-icon` for buttons, `btn-play` for the round play button, `chip` and `chip-toggle` for genres and filters (`chip-toggle` lights up on a checked input, `aria-pressed` or `aria-current`), `badge` for counts, `nav-item` and `menu-toggle` for side menus, `section-title` for a small label over a group. If you write the same class list a third time, add it to `packages/tokens/theme.css`.
- **Don't reset what Tailwind already resets.** Its base styles zero margins and padding and drop list bullets, so `m-0`, `p-0` and `list-none` only belong where they undo something (a `label` or `hint` margin, or a `prose` block).

## Where things live

- `theme.css`: the fonts and Tailwind plugins, over the shared theme in `packages/tokens/theme.css` (the tokens, base styles and shared classes, which localtoolbox uses too). Import it after `@import 'tailwindcss'`.
- `packages/tokens/data-colors.css`: generated from `packages/tokens/colors.json`, the colours the player and the HTML report also use. After editing that file, run `TOKENS_BLESS=1 pnpm -C apps/web vitest run --project server src/lib/ui/data-colors.test.ts`.
- `*.svelte`: the components. Each has stories beside it, and `ui.svelte.test.ts` tests their behaviour.
- **Patterns/Homepage**: the live homepage, rendered from the real `+layout.svelte` and `+page.svelte` with the seed data's projects (`src/routes/page.stories.svelte`), on desktop and on a phone, with its empty and offline states.
- **Proposals/Homepage**: homepage sections the site doesn't have yet (a product shot, mixes, shows, a match demo, tool previews). Ideas, not the live page.

## Checks

`pnpm test:storybook` renders every story in Chromium and fails on an accessibility violation. It runs in `pnpm verify`.
